# Apuntes sobre NTAG213, NTAG215 y NTAG216

Resumen de cómo funcionan estos tres chips y qué contestan, escrito para no
tener que volver a abrir la hoja de datos cada vez. Son datos técnicos,
redactados de cero.

La fuente en la que se basan es la hoja de datos oficial de NXP, que no se
copia aquí ni se incluye en el repositorio:

> NXP Semiconductors, *NTAG213/215/216 — NFC Forum Type 2 Tag compliant IC*,
> hoja de datos rev. 3.2, 2 de junio de 2015.
> <https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf>

Las referencias a apartados y tablas apuntan a ese documento, para poder
contrastar cualquier dato sin buscarlo.

## Qué son los tres

La misma familia con distinta memoria. Comparten juego de comandos, mecanismo
de contraseña, firma de fábrica y contador; solo cambian el tamaño y, en
consecuencia, las direcciones de las páginas especiales.

| | NTAG213 | NTAG215 | NTAG216 |
|---|---|---|---|
| Memoria de usuario | 144 B | 504 B | 888 B |
| Páginas totales | 45 | 135 | 231 |
| Páginas de usuario | 36 (`04h`-`27h`) | 126 (`04h`-`81h`) | 222 (`04h`-`E1h`) |
| Última página | `2Ch` | `86h` | `E6h` |
| Bloqueo dinámico | `28h` | `82h` | `E2h` |
| CFG0 | `29h` | `83h` | `E3h` |
| CFG1 (ACCESS) | `2Ah` | `84h` | `E4h` |
| PWD | `2Bh` | `85h` | `E5h` |
| PACK | `2Ch` | `86h` | `E6h` |

La memoria va en páginas de 4 bytes y siempre se direcciona por página, nunca
por byte.

## Cómo se identifican

- **ATQA**: `00 44h`, igual en los tres. Se transmite con el byte bajo
  primero, así que por el aire va `44 00`.
- **SAK**: `00h`, igual en los tres.
- **GET_VERSION**: 8 bytes que distinguen el modelo (tabla 28).

| Byte | Contenido | Valor |
|---|---|---|
| 0 | Cabecera fija | `00h` |
| 1 | **Fabricante** | `04h` = NXP |
| 2 | Tipo de producto | `04h` = NTAG |
| 3 | Subtipo | `02h` |
| 4 | Versión mayor | `01h` |
| 5 | Versión menor | `00h` |
| 6 | **Tamaño** | `0Fh` / `11h` / `13h` según 213, 215 o 216 |
| 7 | Protocolo | `03h` = ISO/IEC 14443-3 |

Los dos bytes que importan para reconocer el chip son el **1** (fabricante) y
el **6** (tamaño). Un NTAG216 auténtico de NXP contesta
`00 04 04 02 01 00 13 03`.

El byte de tamaño no es el número de bytes: sus 7 bits altos son un exponente
*n* y la memoria de usuario vale 2ⁿ si el bit bajo es 0, o algo entre 2ⁿ y
2ⁿ⁺¹ si es 1. Por eso `13h` (n=9, bit bajo 1) corresponde a los 888 bytes del
NTAG216, que quedan entre 512 y 1024.

Además, el UID de un chip NXP auténtico empieza por `04h`.

## Páginas de configuración

Las cuatro últimas páginas de cada modelo. Su disposición es idéntica en los
tres (tabla 8):

| Página | Byte 0 | Byte 1 | Byte 2 | Byte 3 |
|---|---|---|---|---|
| CFG0 | MIRROR | RFUI | MIRROR_PAGE | **AUTH0** |
| CFG1 | **ACCESS** | RFUI | RFUI | RFUI |
| PWD | contraseña de 4 bytes | | | |
| PACK | acuse de 2 bytes | | RFUI | RFUI |

**AUTH0 es el byte 3 de CFG0, el último.** No hay variantes ni ambigüedad.
Para proteger desde la página 4 hay que dejar CFG0 como `xx xx xx 04`
conservando los tres primeros bytes, y para quitar la protección, `xx xx xx FF`.

El byte **ACCESS** reparte así sus bits (tabla 10):

| Bit | Campo | Qué hace |
|---|---|---|
| 7 | PROT | 0 = la contraseña solo protege escribir; 1 = también leer |
| 6 | CFGLCK | 1 = configuración cerrada para siempre |
| 5 | RFUI | — |
| 4 | NFC_CNT_EN | 1 = contador de lecturas activado |
| 3 | NFC_CNT_PWD_PROT | 1 = el contador pide contraseña |
| 2-0 | AUTHLIM | Intentos fallidos tolerados; 000 = sin límite |

Valores de fábrica: AUTH0 = `FFh` (sin protección), ACCESS = `00h`,
**PWD = `FF FF FF FFh`** y PACK = `0000h`. Ojo con el PWD: de fábrica es todo
unos, no ceros.

## La contraseña

Se verifica con PWD_AUTH mandando los 4 bytes del PWD. Si coinciden, la
etiqueta contesta con el PACK y pasa al estado *autenticado*; si no, contesta
NAK.

Lo que hay que tener claro:

- **AUTH0 marca desde qué página empieza la protección.** Las páginas por
  debajo quedan libres pase lo que pase.
- **PROT decide el alcance.** Con PROT=0 solo se protege escribir; con PROT=1
  tampoco se puede leer.
- **Estando autenticado, los comandos se comportan igual que en una etiqueta
  sin proteger.**
- **PWD y PACK nunca se pueden leer.** Al leer esas páginas la etiqueta
  devuelve ceros en lugar de su contenido.
- **AUTHLIM cuenta los fallos.** Con un valor distinto de 000, cada
  autenticación fallida se anota, y al llegar al límite la zona protegida
  queda cerrada de forma permanente: a partir de ahí falla toda
  autenticación, incluso con la contraseña correcta. Una autenticación buena
  antes de llegar al límite pone el contador a cero.
- **CFGLCK cierra la configuración para siempre**, salvo PWD y PACK, que
  siguen siendo escribibles. El cierre no surte efecto hasta que la etiqueta
  se apaga y vuelve al campo.

## Qué pasa exactamente con la lectura protegida

Con PROT=1 y AUTH0 apuntando a la página 4, sin autenticarse (apartado 10.2):

- Leer una página **igual o mayor que AUTH0** devuelve NAK.
- Leer una página **por debajo de AUTH0** funciona, y el mecanismo de
  *roll-over* hace que la lectura dé la vuelta justo antes de la página de
  AUTH0 en lugar de invadir la zona protegida.

Las páginas de configuración quedan dentro de la zona protegida siempre que
AUTH0 apunte por debajo de ellas, que es el caso en cuanto se protege
cualquier parte de la memoria de usuario: con PROT=1, CFG0 tampoco se deja
leer sin autenticarse.

## Bloqueo permanente

Aparte de la contraseña, que se puede quitar, hay dos mecanismos que no tienen
vuelta atrás:

- **Bytes de bloqueo estáticos**, en la página `02h`. Cubren las páginas `03h`
  a `0Fh`. Valor de fábrica `00 00h`.
- **Bytes de bloqueo dinámicos**, en `28h` / `82h` / `E2h` según el modelo.
  Cubren desde la página `10h` en adelante, con granularidad de 2 páginas en
  el NTAG213 y de 16 páginas en el NTAG215 y el NTAG216.

Una página bloqueada así no se puede reprogramar con ningún comando de
escritura. No es lo mismo que la protección por contraseña.

## Contador de lecturas

Contador de 24 bits que sube solo, y solo hacia arriba. Se incrementa en el
primer READ o FAST_READ después de que la etiqueta entre en el campo. Se
activa con NFC_CNT_EN, se lee con READ_CNT o a través del *mirror*, y se puede
proteger con NFC_CNT_PWD_PROT. Al llegar a `FF FF FFh` se queda ahí.

El NTAG210 y el NTAG212 no lo llevan; los tres de estos apuntes sí.

## Juego de comandos

| Comando | Código | Devuelve | Notas |
|---|---|---|---|
| GET_VERSION | `60h` | 8 bytes | Sin argumentos |
| READ | `30h` | 16 bytes | Cuatro páginas desde la indicada, con roll-over |
| FAST_READ | `3Ah` | Variable | Dos direcciones; la final ≥ la inicial |
| WRITE | `A2h` | ACK | Una página de 4 bytes |
| COMPATIBILITY_WRITE | `A0h` | ACK | Lo mismo en dos tramas, para lectores antiguos |
| READ_CNT | `39h` | 3 bytes | Contador de lecturas |
| PWD_AUTH | `1Bh` | 2 bytes (PACK) | Verifica la contraseña |
| READ_SIG | `3Ch` | 32 bytes | Firma ECC de fábrica |

Rangos de página válidos: leer admite de `00h` al final del modelo; escribir,
de `02h` en adelante. Salirse del rango devuelve NAK.

FAST_READ puede traerse la memoria entera de una vez, pero no hay troceado: el
lector tiene que poder recibirlo todo en una sola respuesta.

## Acuses de recibo

La etiqueta contesta con 4 bits (tabla 23):

| Código | Significado |
|---|---|
| `Ah` | ACK: comando aceptado |
| `0h` | Argumento inválido, típicamente una página que no existe |
| `1h` | Error de paridad o de CRC |
| `4h` | Desbordamiento del contador de autenticaciones fallidas |
| `5h` | Error al grabar la memoria |

## Firma de originalidad

READ_SIG devuelve 32 bytes de firma ECC grabados en fábrica, distintos en cada
chip y que no se pueden cambiar. Es la vía de NXP para demostrar que el
silicio es suyo.
